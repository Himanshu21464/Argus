When JWST captures a transmission spectrum of a hot Jupiter, retrieval codes bin it down to make MCMC tractable — discarding the dynamic range an $11 B telescope was built to deliver. Argus is that kernel. The wedge into a substrate that eventually compiles photons into physics across exoplanets, lensing, and interferometry.

§01   The pain

JWST is producing data we cannot fully analyze.

A single JWST transmission spectrum of a hot Jupiter contains, in principle, parts-per-million constraints on H2O, CO2, CH4, NH3, hazes, clouds, the temperature-pressure profile, and atmospheric circulation. Extracting any of that requires a Bayesian inversion against a forward radiative-transfer model.

One forward call sweeps line-by-line opacity over $10^5$–$10^7$ wavenumber points across multiple molecular species and hundreds of atmospheric layers. That's seconds-to-minutes per call on CPU. One MCMC retrieval needs $10^6$–$10^7$ forward calls. Production codes bin the spectrum to make the math fit.

The dynamic range JWST exists to deliver is being thrown away to fit a 2008 algorithm.

FRAGMENTATION

Five PhD codebases. Zero composition.

  • PYTHON TauREx
  • PYTHON POSEIDON
  • PYTHON CHIMERA
  • PY/F90 petitRADTRANS
  • JAX ExoJAX2 — validates the differentiable approach

Each owns its own opacity format, atmosphere parameterization, prior conventions. Cross-code comparisons are heroic. None expose gradients through the full forward model.

§02   What Argus is

Five layers. One bijection. Photons → atmospheres.

A C++20 / CUDA core for differentiable line-by-line radiative transfer, with an autograd-aware intermediate representation and a built-in simulation-based inference engine. Composable, GPU-resident, vendor-neutral.

§03   Why a C++ kernel with autograd is non-negotiable

The hot path is C++. Always.

1

Throughput

One JWST retrieval needs $10^6$–$10^7$ RT forward evaluations. Each touches GB-scale opacity tables. Python wrappers cost 10–100× in the hot path.

2

Determinism

Bit-reproducible posteriors across hardware and years are required for biosignature claims. Python autograd toolchains drift; an explicit C++ tape does not.

3

GPU residency

Opacity grids are 1–100 GB per molecule. They must stay on device across the whole retrieval. Python orchestration constantly bounces them through host memory.

4

Composability

The same RT primitive must be callable from MCMC, NF posterior, and gradient-based optimization without rewriting.

5

Vendor longevity

A 2026 telescope takes data until 2050+. The kernel that processes its photons must compile in 2050.

Python and Julia bindings live above the kernel — for retrieval scripts, agent reasoning, plotting, UI. The hot path is C++.

§04   The forward model

End-to-end in 40 lines.

The M1 kernel ships Atmosphere, OpacityKernel, TransmissionModel, and the Argus IR. The example below is what's in examples/01_transmission_spectrum.cpp right now, today.

examples/01_transmission_spectrum.cpp 
// 1. Build a 40-layer isothermal H2O atmosphere.
using namespace argus;
Species h2o{"H2O", 18.015};
Atmosphere atm = isothermal(1200.0,    // T [K]
                            1.0e-6,     // P_top [bar]
                            1.0e2,      // P_bot [bar]
                            40,         // n_layers
                            h2o,
                            1.0e-3);    // VMR

// 2. Attach an opacity kernel.
//    M2 swaps GreyOpacity for HITRAN+CUDA Voigt; this call site does not change.
auto opacity = std::make_shared<GreyOpacity>("H2O", 1.0e-22);

// 3. Forward model.
TransmissionModel model;
model.add_opacity(opacity);

std::vector<double> wavenumber_cm = make_grid(2000.0, 4000.0, 21);
Spectrum s = model.forward(atm, wavenumber_cm);

// 4. Argus IR — content-addressed reproducible runs.
ir::Graph g;
auto a = g.add(ir::NodeKind::kAtmosphere,    "atm");
auto o = g.add(ir::NodeKind::kOpacity,        "h2o_grey");
auto m = g.add(ir::NodeKind::kForwardModel,   "transmission", {a, o});
auto p = g.add(ir::NodeKind::kSpectrum,       "out", {m});

std::cout << g.content_address();   // → 845f876e00f4ea93
✓ Compiles under -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion on GCC 15.
✓ Three smoke tests pass (atmosphere, RT, IR content-addressing).
✓ Zero external runtime dependencies in M1.
§05   The 18-month roadmap

One workstation. Public data only. No telescope required.

  1. M1 · months 1–3

    The IR SHIPPED v0.1

    Typed graphs of opacity sources, atmosphere layers, instrument PSF, observational geometry. Serialization, content-addressed runs, provenance. C++20, zero runtime deps.

  2. M2 · months 3–6

    The kernel

    GPU-resident opacity tables (HITRAN / HITEMP / ExoMol). First differentiable transmission-spectrum solver in C++/CUDA. Validate against petitRADTRANS on the WASP-39b benchmark.

  3. M3 · months 6–9

    The inference engine

    Amortized SBI via normalizing flows. Compare against POSEIDON / CHIMERA on public JWST spectra. Target: 10× speed, equal or better posteriors, no spectral binning.

  4. M4 · months 9–12

    Lensing pass

    Add a strong-lensing forward model in the same IR. Differentiable ray-trace through SIE / EPL profiles. Demonstrates the substrate generalizes beyond exoplanets.

  5. M5 · months 12–18

    Imaging pass

    Differentiable interferometric forward model — gridder + FFT + visibility prediction. Three disjoint sub-fields running on one kernel = the substrate claim.

§06   The substrate

Argus is the wedge. Not the destination.

2026 astronomy has ten computational walls. None of them have a shared C++ substrate. None of them have an LLVM-level IR. Argus picks the smallest, most contained wall — atmospheric retrieval — and proves the substrate by climbing.
